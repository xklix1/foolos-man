2 Database & Data Integrity Risk Analysis

2.1 Will Migration Cause Data Loss or Progress Resets?

No. Zero data loss is guaranteed if the migration follows a non-destructive schema preservation protocol. In the current setup, all player progress is stored inside the players table across two layers:

  • Normalized SQL Columns: username, cash, bank, net_worth, xp, title, job_id, last_seen.
  • Complete State Document: state (JSONB column containing businesses, upgrades, inventory, crypto, stocks, etc.).

The new server-authoritative backend will not drop or alter this table structure. Instead, the Node.js server will load the existing JSONB document upon session login, validate it, maintain it in memory, and persist updates back to the same columns.

2.2 Migration Hazards & Concrete Mitigations

Hazard 1: Split-Brain Direct Writes
Cached client browsers might continue sending direct PostgREST PATCH requests while the new server is live, overwriting balances.

Mitigation: Revoke UPDATE and INSERT permissions for the anon role via Row Level Security (RLS). Direct browser writes will be rejected with HTTP 403, prompting users to reload to the new version.
Hazard 2: Legacy Schema Discrepancies
Older accounts created before certain updates might lack newly added fields (e.g., afkManagerExpiresAt or stocks), potentially causing server-side null pointer errors.

Mitigation: Implement a Schema Sanitizer / Hydrator on the server: playerState = Object.assign({}, defaultInitialState, dbRow.state);. Missing fields are automatically populated without altering existing wealth.

3.2 Server-Authoritative 12-Hour Offline Profit Engine

Under the new architecture, the client code never calculates offline profits. The entire offline simulation executes on the server when the user opens a session: 

// Server-Side Authoritative Offline Algorithm (Executed upon session start)
function calculateOfflineProgress(playerRecord, serverNow) {
  const lastActive = Number(playerRecord.last_active_timestamp || serverNow);
  const rawElapsedSeconds = Math.max(0, Math.floor((serverNow - lastActive) / 1000));
  
  // 1. Strict 12-hour cap enforcement (43,200 seconds)
  const cappedElapsedSeconds = Math.min(43200, rawElapsedSeconds);
  if (cappedElapsedSeconds <= 0) return { earnedCash: 0, elapsed: 0 };

  // 2. AFK Manager coverage analysis
  const managerExpiry = Number(playerRecord.afk_manager_expires_at || 0);
  const isManagerActiveAtExit = managerExpiry > lastActive;
  
  let profitableSeconds = 0;
  if (isManagerActiveAtExit) {
    const managerCoverageEnd = Math.min(serverNow, managerExpiry);
    profitableSeconds = Math.max(0, Math.min(cappedElapsedSeconds, Math.floor((managerCoverageEnd - lastActive) / 1000)));
  }

  // 3. Authoritative supply depletion & business revenue simulation
  const result = simulateProduction(playerRecord.state, profitableSeconds, cappedElapsedSeconds);
  
  // 4. Update state atomically on server
  playerRecord.state.cash += result.earnedCash;
  playerRecord.last_active_timestamp = serverNow;
  
  return result;
}
